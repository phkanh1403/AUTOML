The backend reads the CSV directly; JavaScript does not parse the dataset. At least 12 labeled rows are recommended.
Folder names inside the ZIP are used as class labels (no manual label entry is required): 
dataset.zip
├── Apple/
│   ├── image_001.jpg
│   ├── image_002.jpg
│   └── ... (at least 100 images)
└── Banana/
    ├── image_001.jpg
    ├── image_002.jpg
    └── ... (at least 100 images)
An optional wrapper folder is supported (for example, dataset/Apple/...). Each class folder must contain at least 100 valid, unique JPEG/PNG images. Use one folder for one-class novelty detection, or multiple folders for multiclass classification. The highest confidence must be greater than 64% to return a class label; otherwise, the result is Other.
Labels are inferred from class folder names; no manual labels are required.

MODEL REGISTRY

Every successful training run saves a named model artifact such as apple-image-1.joblib or gender-tabular-2.joblib under data/models/<job_id>/. Image names use class-folder labels joined with &; tabular names use the selected target column. A global sequence is shared across both types and is not reset when models are deleted. The registry is read from backend storage, not browser localStorage. Deleting a model removes its model file, metadata, and associated dataset artifacts from disk.
